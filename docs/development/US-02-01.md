# US-02-01 - Inscription client securisee

## Objectif

Permettre a un visiteur de creer un compte client securise afin de pouvoir deposer et suivre ses dossiers.

## Perimetre implemente

Cette implementation couvre les exigences suivantes :

- Formulaire d'inscription avec :
  - email
  - mot de passe (min 12 caracteres, au moins 1 majuscule, 1 chiffre, 1 caractere special)
  - prenom
  - nom
  - date de naissance
- Validation de l'email par lien de confirmation
- Acceptation obligatoire des CGU et de la politique de confidentialite
- Message de confirmation affiche apres inscription
- Chiffrement des donnees personnelles au repos via `pgcrypto`

## Vue d'ensemble technique

L'US a ete implementee en ajoutant :

- un module d'authentification dedie a l'inscription
- des schemas de validation stricte des entrees
- des champs supplementaires sur l'entite `users`
- une migration Alembic pour la structure et le chiffrement des donnees
- deux pages frontend (`/inscription`, `/confirm-email`)

## Backend

### 1) Nouveaux endpoints API

Fichier : `backend/app/api/v1/endpoints/auth.py`

- `POST /api/v1/auth/register`
  - cree un compte client
  - applique les validations metier
  - genere un token de confirmation email
  - stocke uniquement le hash SHA-256 du token
  - retourne un message de confirmation
- `GET /api/v1/auth/confirm-email?token=...`
  - valide le token de confirmation
  - active l'email (`email_verified = true`)
  - invalide le token (suppression des champs de verification)

Integration du routeur :

- `backend/app/api/v1/router.py`

### 2) Validation des donnees d'inscription

Fichier : `backend/app/schemas/auth.py`

- `RegisterRequest` :
  - validation email (format)
  - validation mot de passe (regex securite)
  - validation consentements (`accepted_cgu`, `accepted_privacy_policy` obligatoirement `true`)
- `RegisterResponse` et `EmailVerificationResponse` :
  - DTO de sortie homogenes

### 3) Evolution du modele User

Fichier : `backend/app/models/user.py`

Ajouts :

- `birth_date` (date de naissance)
- `cgu_accepted_at` (horodatage consentement CGU)
- `privacy_accepted_at` (horodatage consentement politique de confidentialite)
- `email_verification_token` (hash du token)
- `email_verification_sent_at`
- `email_verification_expires_at`

Chiffrement au repos :

- `first_name` et `last_name` sont desormais mappes avec un type chiffre `PgcryptoEncryptedText`

### 4) Type SQLAlchemy de chiffrement pgcrypto

Fichier : `backend/app/db/types.py`

- ajout du type `PgcryptoEncryptedText`
- en PostgreSQL :
  - ecriture : `pgp_sym_encrypt(...)`
  - lecture : `pgp_sym_decrypt(...)`
- hors PostgreSQL (ex: SQLite tests) :
  - fallback transparent en texte

### 5) Configuration

Fichier : `backend/app/core/config.py`
 
Nouvelles variables :

- `PII_ENCRYPTION_KEY` : cle de chiffrement des donnees personnelles
  - fallback sur `SECRET_KEY` si absente
- `FRONTEND_BASE_URL` : base publique pour generer le lien de confirmation email

## Migration base de donnees

Fichier : `backend/alembic/versions/002_us_02_01_client_registration_security.py`

Actions principales :

- activation de l'extension `pgcrypto` (PostgreSQL)
- ajout des colonnes metier liees a l'inscription
- creation d'une contrainte d'unicite sur `email_verification_token`
- conversion/chiffrement de `first_name` et `last_name` en `bytea` via `pgp_sym_encrypt`
- remplissage de valeurs par defaut pour les enregistrements existants avant passage en `NOT NULL`

Downgrade :

- dechiffrement `first_name` / `last_name` vers `varchar`
- suppression des colonnes ajoutees

## Flux fonctionnel

1. Le visiteur ouvre `/inscription`
2. Il complete le formulaire et accepte les deux consentements
3. Le backend valide les donnees et cree le compte (`email_verified = false`)
4. Un token de verification est genere (hash stocke en base)
5. Un lien de confirmation est genere pour l'utilisateur
6. L'utilisateur ouvre le lien (`/confirm-email?token=...`)
7. Le backend valide le token puis marque l'email comme confirme

---

## Securite et conformite

- mot de passe robuste impose des la creation du compte
- consentements legaux obligatoires et traces horodatage
- token de confirmation non stocke en clair (hash SHA-256)
- donnees personnelles chiffrees au repos en PostgreSQL (`pgcrypto`)

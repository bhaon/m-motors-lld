# US-02-03 - Réinitialisation du mot de passe par email

## Objectif

Permettre à un client de retrouver l'accès à son compte lorsqu'il a oublié son mot de passe, via un lien envoyé par email.

## Parcours utilisateur

1. Depuis la page `connexion`, l'utilisateur clique sur le lien `Mot de passe oublié ?`.
2. Il saisit son email dans la page `mot-de-passe-oublie`.
3. Le backend enregistre un token de reset (hashé) expirant au bout de 1 heure et envoie l'email de réinitialisation.
4. L'utilisateur clique sur le lien reçu et arrive sur `reset-password?token=...`.
5. Il saisit son nouveau mot de passe et confirme.
6. Le backend valide le token, met à jour le mot de passe et supprime immédiatement le token de reset.

## Implémentation technique

### Backend

- Modèle `User` enrichi avec :
  - `password_reset_token` (unique, nullable)
  - `password_reset_sent_at` (nullable)
  - `password_reset_expires_at` (nullable)
- Migration Alembic : `003_us_02_03_password_reset.py`
- Nouveaux endpoints :
  - `POST /api/v1/auth/forgot-password`
    - Entrée : `{ "email": "..." }`
    - Réponse générique (anti-énumération)
  - `POST /api/v1/auth/reset-password`
    - Entrée : `{ "token": "...", "new_password": "..." }`
    - Vérifie la validité et l'expiration du token (1h)
    - Met à jour `hashed_password`
    - Invalide le token (champs reset remis à `null`)
- Emailing :
  - Nouveau template HTML de reset
  - Nouvelle fonction `send_password_reset_email(...)`

### Frontend

- Page de connexion :
  - lien `Mot de passe oublié ?` vers `/mot-de-passe-oublie`
- Nouvelle page `/mot-de-passe-oublie` :
  - formulaire email
  - appel `POST /api/v1/auth/forgot-password`
- Nouvelle page `/reset-password` :
  - lecture du token dans l'URL
  - saisie + confirmation du nouveau mot de passe
  - appel `POST /api/v1/auth/reset-password`

## Critères DoD couverts

- Lien `Mot de passe oublié ?` disponible sur la page de connexion : oui.
- Email de réinitialisation envoyé rapidement : envoi déclenché immédiatement pendant le traitement de la requête.
- Lien de réinitialisation expirant après 1 heure : oui (`password_reset_expires_at = now + 1h`).
- Ancien mot de passe invalidé immédiatement après changement : oui (écrasement du hash et invalidation du token de reset).

## Tests ajoutés

### Backend unitaires

- émission token reset + email envoyé
- réponse générique si email inconnu
- reset réussi : nouveau mot de passe valide, ancien invalide
- rejet token expiré

### Backend intégration

- scénario de bout en bout :
  - register
  - forgot-password
  - reset-password
  - ancien mot de passe rejeté
  - nouveau mot de passe accepté

### Frontend

- présence du lien `Mot de passe oublié ?` sur connexion
- page mot de passe oublié : envoi + message de succès
- page reset password : reset réussi
- page reset password : erreur si confirmation différente

# US-03-02 - Upload des pièces justificatives en ligne

## Objectif

Permettre à un client d'uploader ses pièces justificatives sans déplacement, avec stockage objet sécurisé et vérification d'intégrité.

## Parcours utilisateur

1. Le client confirme la création de son dossier depuis la fiche véhicule.
2. Une modale `Dépôt des pièces justificatives` s'ouvre immédiatement.
3. Le client uploade les 5 types requis : `CNI`, `Permis de conduire`, `Justificatif de revenus`, `Justificatif de domicile`, `RIB`.
4. Chaque pièce validée affiche un indicateur visuel `✓ Uploadé` en vert.
5. Les fichiers sont envoyés sur MinIO via URL pré-signée, puis confirmés côté backend avec contrôle SHA-256.

## Implémentation technique

### Backend

- Nouvelles variables de configuration S3/MinIO dans `app/core/config.py` :
  - `S3_ENDPOINT_URL`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_REGION`, `S3_PRESIGN_EXPIRES_SECONDS`
- Nouveau service `app/services/object_storage.py` :
  - client S3 (boto3) compatible MinIO
  - création bucket à la volée si absent
  - génération URL pré-signée PUT
  - vérification checksum SHA-256 en relecture objet
- API dossier enrichie (`app/api/v1/endpoints/dossiers.py`) :
  - `POST /api/v1/dossiers/{id}/pieces/upload-init`
    - validation type MIME (`application/pdf`, `image/jpeg`, `image/png`)
    - validation taille max 10 Mo
    - validation checksum fourni
    - retour URL pré-signée + headers d'upload
  - `POST /api/v1/dossiers/{id}/pieces/upload-complete`
    - vérification checksum réel de l'objet MinIO
    - upsert de `PieceJustificative` (type pièce, filename, s3_key, checksum)

### Frontend

- Nouveau utilitaire `frontend/src/lib/checksum.ts` :
  - calcul SHA-256 navigateur
  - conversion hex -> base64 pour header S3
- Nouvelle modale `frontend/src/components/DossierPiecesModal.tsx` :
  - liste des 5 pièces obligatoires
  - upload fichier par fichier (PDF/JPG/PNG, max 10 Mo)
  - workflow upload-init -> PUT MinIO -> upload-complete
  - checkmark vert après succès
- `CataloguePage` mis à jour pour ouvrir la modale pièces après création dossier.

### Déploiement MinIO (Kubernetes)

- Nouveau manifeste `k8s/base/minio.yaml` :
  - Deployment MinIO
  - Service `minio` (ports 9000/9001)
  - PVC `minio-pvc`
- Ajout dans `k8s/base/kustomization.yaml`
- Backend injecté avec variables MinIO via ConfigMap + Secret (`minio-credentials`)
- ConfigMaps `dev/staging/production` enrichies avec `S3_ENDPOINT_URL` et `S3_BUCKET`
- Secrets `dev/staging/production` enrichis avec `MINIO_ROOT_USER` et `MINIO_ROOT_PASSWORD`
- NetworkPolicies `dev/staging/production` enrichies :
  - backend -> minio autorisé sur 9000
  - policy dédiée `minio-policy` (ingress backend uniquement)

## Critères DoD couverts

- Types acceptés PDF/JPG/PNG + max 10 Mo : oui (backend + frontend).
- Pièces requises CNI/permis/revenus/domicile/RIB : oui (modal dédiée 5 types).
- Confirmation visuelle par checkmark vert : oui (`✓ Uploadé`).
- Stockage via MinIO et URL pré-signée : oui.
- Checksum SHA-256 calculé et vérifié : oui (calcul frontend + vérification backend avant persistance).

## Tests ajoutés

### Backend unitaires

- refus upload-init si fichier > 10 Mo
- flux upload-init + upload-complete avec persistance `PieceJustificative`
- rejet upload-complete si checksum non conforme

### Frontend

- ouverture modal pièces après création dossier
- upload d'une pièce et affichage du checkmark vert
- annulation avant création (modale de confirmation) sans appel API
